# Batched issue resolution — MX Bikes iOS native pipeline

**Governing project priorities:** [The Four Commandments](https://github.com/NyerahMT/ARM64-Lab/blob/main/docs/four-commandments.md). In order: (1) work in related dependency batches rather than isolated CRT-function milestones; (2) automate analysis/lifting/differentials before rebuilding things by hand; (3) probe the reachable engine path concurrently with required CRT work; (4) measure progress by verified native startup, engine initialization, first real frame, and interactive original menu. Preserve the tests and private-binary restrictions below; do not substitute gate counts for game progress.

Default to **grouping related failures by root cause and API/instruction family** rather than patching one instruction or one CI symptom per iteration.

1. **Inventory first:** list unsupported instruction families, branch edges, guest memory/addressing models and missing imported APIs. Sort by common cause and reachable startup frontier. Distinguish actual x64 reference behavior, tool limitations, test fixture mistakes and CI environment failures.
2. **Batch the fix:** change the shared translator or runtime primitive, not a game-specific one-line workaround, where the cases genuinely share semantics. Validate operands, flags, guest pointer bounds, and Win64 ABI; reject unsupported forms clearly.
3. **Test the matrix at once:** include success, failure, fallback/retry, boundary, invalid-input and regression cases. Compare original x64 against host C and compiled AArch64 under deterministic fixtures. Never count a synthetic Windows call as a real API implementation.
4. **One integration gate:** commit a coherent code+test+CI batch, pin the public translator SHA in the private original-game workflow and let that one run exercise the new frontier **and all previously passing gates**. Capture the failing result once and repair the *entire* related class before re-running.
5. **Report only verified coverage:** static decode ≠ translated; object compilation ≠ execution; isolated branch proof ≠ joined end-to-end startup; green CI ≠ iPhone gameplay. Keep all proprietary game bytes, generated original-game C/LLVM/ELF and assets off public artifacts.
6. **Next batch:** choose the next reachable control-flow unit (basic blocks and imported-call dependencies), not an arbitrary quantity of instructions.

Current accepted checkpoints are the original first CRT initializer (39 decoded instructions, 10/10 differential), followed by the second CRT's 12-instruction joined region (12/12), and the original compare-exchange retry CFG (18/18). The first consolidated six-gate batch is **6/6 green** ([batch CI](https://github.com/NyerahMT/ReflexBuildInput/actions/runs/39304882475)). The remainder of the second CRT and iOS startup are still pending.
