# Development gates

The percentages in project updates refer to explicit milestones, not a fraction of game code translated.

| Gate | Criteria | Status |
| --- | --- | --- |
| D0 | Inventory a local Windows PE32+ input safely | Complete locally |
| D1 | Extract limited x86-64 return-sequence candidates, generate C, compile AArch64 object | Verified in private CI against original MX Bikes input; still only isolated byte-pattern lift |
| D2 | Establish true callable function boundaries and differential reference behavior | In progress: Ghidra headless startup call graph plus one x64-vs-C-vs-ARM64 200-case cross-product differential proof |
| D3 | Scalable lifting of original code, indirect branches, guest stack, Windows x64 ABI and exceptions | In progress: restricted scalar SSE lifter translated one 24-instruction original function automatically; most ISA/control flow/runtime features not yet implemented |

| D6 | Render interactive original menu | Not started |
| D7 | Gameplay, controller input, iOS device build | Not started |

- The x64 vector-cross-product routine at RVA 0x267AE0 (24 instructions) was run under Unicorn x64. Both a manually written C equivalent and a **restricted automatic Capstone x64 SSE-to-C lift** were compiled to AArch64 and executed under Unicorn ARM64. All 200 normal-range float32 test pairs matched bit-for-bit across original x64, native C, generated C, and both ARM64 binaries (2026-10-17). This is a single supported straight-line function, not general game recompilation.
- Ghidra 12.1.4 headless, using the **verified original private executable**, recognized 4,903 functions and 122 thunks, including the entry function at RVA 0x2ab31c (2026-10-17).
- Bounded four-edge-deep static traversal from that entry found 94 nodes and 101 call edges. Of these, 22 distinct external API names were identified (Kernel32, User32, WinMM, MSVCR90, Steam API). The main startup initialization branch passes through RVA 0x136710; candidate high-fanout internal call sites include RVA 0x133e80 (26 mapped callees) and RVA 0x135cd0 (21 mapped callees).

- The Ghidra headless toolchain is pinned, SHA-256 verified and cached in private CI for repeatability. Exports contain metadata only.
- Startup roadmap from the 2026-10-17 Ghidra snapshot grouped 24 static external-call edges into 22 distinct API names, spread across CRT/process, timing, file paths, window/message, drawing, and Steam lifecycle categories. 53 internal graph nodes reached the four-level analysis cutoff, so the report is not a complete call graph.

Native deterministic unit tests and a freestanding AArch64 cross-compile passed in CI (2026-10-17). A guest import/Windows ABI bridge and iOS-specific clock sources are not yet implemented.
- Expanded five-level Ghidra analysis (2026-10-17): 317 static graph nodes, 390 call edges, 76 external-call edges to 59 distinct API names, with 186 depth-limit nodes still unexplored. The analyzed code includes 17,695 sampled instructions and 86 distinct mnemonics; these are static observations, not executed instructions.
- Newly exposed dependencies include SteamAPI_Init, OpenGL32.wglCreateContext/wglMakeCurrent, GDI SwapBuffers, User32.CreateWindowExA, Kernel32.LoadLibraryA/GetProcAddress, and associated teardown. All 59 observed names were assigned a compatibility category in the refreshed roadmap.
- Original Win64 register-argument import-dispatch scaffolding now routes six timing APIs into deterministic clock helpers through a bounded guest-memory write interface. Native synthetic tests and freestanding AArch64 object compilation passed. No actual original Win64 imports have been invoked through this adapter yet.
- Official rev.ng successfully created its PE/COFF parse-binary model from the original executable. A subsequent full-program LLVM lift failed with exit code 137 under a 6 GiB container memory limit; this is a resource-constrained failure, not proof that lifting is unsupported.
- A smaller launcher PE control also failed to finish rev.ng's full LLVM lift within a four-minute timeout (exit 124). It wrote a 9,897,392-byte intermediate file, but its validity/completeness was not verified. Do not describe either rev.ng lift as successful.
- The exact 18-byte original x64 entry wrapper at RVA 0x2ab31c contains `sub rsp,0x28`, a direct call to RVA 0x2ab954, `add rsp,0x28`, and a tail `jmp` to RVA 0x2ab02c. A controlled Unicorn x64 run executed all four actual wrapper instructions with a synthetic callee return, checked stack restoration, and reached the tail destination.
- The original entry wrapper's stack/call/tail-transfer **control effects** were automatically modeled as portable C and compiled to a 160-byte AArch64 ELF function, executed under Unicorn ARM64 with matching structural results. **Neither original startup callee was compiled or executed on ARM64.**
- The actual original CRT security-cookie initializer at RVA 0x2ab954 spans 179 bytes and 39 statically decoded instructions. In private x64 emulation, **36 original instructions from that function plus 4 original wrapper instructions executed**; five Kernel32 calls were answered by synthetic import stubs, two original PE global writes occurred, and the function returned correctly with the stack restored.
- The following CRT startup routine begins at RVA 0x2ab02c and spans a 518-byte unwind interval with 126 statically decoded instructions. It uses Windows GS/TEB state, `lock cmpxchg`, imported Win32 calls, and branching; **this larger routine has not been executed in the current harness**.
- On 2026-10-17, a bounded original x64 CRT startup harness with synthetic TEB and Win64 import responses executed **1,241 original MX Bikes x64 instructions**, observed 148 original-image global writes, and reached all five original initializer callback entries across the _initterm_e and _initterm tables. Real original callbacks were invoked via ABI-conformant synthetic guest call trampolines; unsupported dependencies stopped the trace.
- A concrete loader bug was isolated: imported CRT data symbol _acmdln had incorrectly been represented as executable RET (0xC3). Mapping it as a writable pointer-to-command-line data slot removed the fault at original RVA 0x2ab144. This is evidence about host import-loader behavior, not native game startup.
- A prior x64 trace stopped at MSVCR90 fopen("steam_api64.dll", "rb"). Private ZIP inventory confirmed one matching DLL in Game.zip, 250,656 uncompressed bytes. This **formerly missing file bridge has since been implemented for private, read-only emulation** (see latest finding below).
- The Win64 CRT callback trampoline and synthetic pointer-token model passed their independent ARM64-Lab tests. The pointer codec is not Microsoft's original algorithm and isn't production-quality Windows emulation.
- A bounded, **read-only guest CRT file bridge** now implements synthetic Win64 opaque handles and actual bytes for fopen, fread, fseek, ftell, fclose, fgetc, feof, ferror, and rewind. The public ARM64-Lab tests use synthetic data, including member counts, seek behavior, EOF, invalid handles, and traversal refusal; CI passed. The private game job loads original Steam DLL data in-memory directly from the user's archived files, without exporting any commercial bytes.
- In private Actions on 2026-10-17, original MX Bikes code executed **4,266,952 x64 instructions**, made 251 fread calls, received the **full 250,656 bytes** of the real steam_api64.dll, and closed the file. After modeling SteamAPI_RestartAppIfNecessary with an explicitly synthetic no-restart response, a second trace executed **4,266,955 x64 instructions** and stopped at the real SteamAPI_Init import. All 5 original CRT initializer entries were reached; the main engine, graphics, and Steam SDK have **not** been initialized.
- The new boundary is SteamAPI_Init. The harness intentionally does not report a real Steam session or return fabricated Steam interface pointers. File reading and original CRT instruction execution occurred under **Unicorn x64 emulation**, not ARM64 recompilation or iPhone execution.
- Private audited DLL dependency inventory (October 17/18, 2026) found exactly **12 imported DLLs and 320 statically imported names**. The prior bounded x64 trace observed 290 import invocations across 25 distinct name entries; all names matched the PE's static import inventory. The counts are invocations, not unique functions or translated coverage.
- Import concentrations: 127 MSVCR90.dll, 70 OPENGL32.dll, 40 USER32.dll, 30 KERNEL32.dll, 18 WS2_32.dll, 14 GDI32.dll and 10 STEAM_API64.dll. Only STEAM_API64.dll was found among the supplied private archived dependency DLL basenames. Microsoft DLLs must be replaced by compatible APIs rather than treated as native iOS binaries.
- The audit explicitly distinguished one confirmed CRT **data import**, MSVCR90.dll!_acmdln, from callable functions. It classifies 5 statically imported timing APIs with a portable C implementation, 7 with a private x64-only file bridge, 16 with synthetic x64-only responses, one SteamAPI_Init import requiring genuine Steam integration, and 290 other imports needing classification or implementation. This does NOT mean 290 APIs are required before initial startup.
- A typed C runtime import registry now routes only the six supported timing interfaces (five imported in this executable) and flags the confirmed data import and Steam lifecycle functions as non-callable/unsupported. Native host tests plus AArch64 cross-compilation passed; no simulated Steam success is permitted in the native registry. Its code is not wired to a translated game or an iPhone build.
- A restricted **x64 RIP-relative imported-CALL AOT lifter** now disassembles and verifies the import-table address, emits typed C calling the portable native registry, enforces Win64 caller-stack alignment, and fails closed on unsupported instructions and imports. In public CI, a six-instruction synthetic Win64 reference with two imports was executed in Unicorn x64, compiled for host and ARM64 ELF, then executed in Unicorn ARM64 with native C runtime imports; all checks passed. SteamAPI_Init was not falsely reported successful.
- Private CI located 1,470 potential imported RIP-relative machine-code instruction positions in the original MX Bikes .text (1,350 CALL, 120 JMP). Of these, 11 CALL instruction candidates target currently implemented timing services; there are zero matched timing-import JMP thunks currently supported by the restricted translator. A byte-pattern/instruction candidate is not automatically a verified function boundary.
- **First authentic original-code-to-ARM64 import instruction proof (October 17/18, 2026):** the original six-byte CALL at MX Bikes RVA **0x2AB9AE** was verified to reference the PE IAT entry KERNEL32.dll!GetTickCount. Its x64 instruction ran with a synthetic imported API RET under Unicorn x64. The automatically generated C imported-call model was linked to the actual native timing registry, compiled for host and AArch64 ELF, and run under Unicorn ARM64. Both returned RAX=1234 with correct guest stack behavior. **Only that single original imported CALL instruction was translated—not its enclosing function or the executable entry path.**
- **Batch of three additional complete original MX Bikes SSE functions translated and differentially executed on ARM64 (October 17/18, 2026):** strict unwind-backed survey inspected 6,275 bounded ranges and found four candidate complete branch-free routines supported by the existing instruction-by-instruction SSE lifter, including the previously tested cross product. New originals at RVA **0x266D80 (35 x64 instructions)**, **0x266E20 (32)** and **0x266EB0 (32)** each passed **200/200 bitwise x64-vs-generated ARM64 Unicorn differential tests**, 600/600 total, with host C output also checked. Each original function was compiled to an isolated AArch64 ELF object in private CI. Together with prior RVA 0x267AE0 (24), four entire original routines (123 instructions) have matching differential results.
- These four routines contain no imports or branches. This demonstrates correctness for a restricted SSE subset, **not** scalable whole-program recompilation, a native Win64 loader, game startup, or iOS execution. Original commercial bytes, generated derived C and native objects remain unshared; only report metadata was published.
- **Fifth complete original Win64 function on ARM64 (October 17/18, 2026):** original RVA **0x258BB0** is an unwind-backed, 17-instruction straight-line integer memory writer. A new strict signature-checked lifter derives the global counter/record-array RIP-relative addresses and five indexed field offsets, generating C for a bounded record index. It tested correct Win64 fifth/sixth stack arguments, RBX preservation, a 72-byte per-record layout, and exact counter/record/destination contents. The original x64 body and generated host C/AArch64 code passed **128/128 bitwise differential cases**, with **72 AArch64 machine-code bytes**. The generator is **pattern-specific**, not general x64 instruction translation, and the test intentionally bounds the counter to 0..7.
- There are now **five fully translated, differential-verified original function bodies** covering **140 x64 instructions** (24+35+32+32+17): four SSE math routines and one integer/global-memory record writer. Total recent differential cases: 200 for the prior cross-product + 600 for new SSE functions + 128 for indexed record writer. All matching in their explicitly tested input domains. The original full engine and startup routines remain untranslatable through these narrow tools.
- **First original multi-basic-block conditional-branch region verified in AArch64 (October 17/18, 2026):** private original unwind-backed interval RVA **0x2B212C–0x2B215E** (11 decoded x64 instructions) was decoded and translated by a new restricted instruction-to-C CFG lifter. It implements register/memory MOV, TEST, JE/JNE, fixed RSP adjustment and RET using a bounded guest address map, checks branch targets and rejects unhandled x64 instructions. The original branch region ran in Unicorn x64 and the generated C ran on native host and as freestanding AArch64 ELF in Unicorn: **128/128 bitwise cases matched**, covering 64 taken and 64 untaken branches. Invalid guest pointers were rejected rather than dereferenced.
- **Important boundary:** this 11-instruction unwind interval begins after an apparent prologue; it must be called a **translated original control-flow region**, not a recovered full function. Existing **five verified complete branch-free original functions (140 instructions)** remain a separate total. The CFG lifter currently supports only a strict integer/memory/zero-flag subset, not arbitrary control flow, guest exception semantics, or startup execution on ARM64. Outputs remain metadata-only in private CI.

- **Second original MX Bikes conditional-flow region successfully ran under AArch64:** real unwind-backed RVA **0x1FC710–0x1FC736** (14 original x64 instructions), comprising indexed array accumulation, increment, signed CMP/JL back-edge, and a Win64 saved-register epilogue.
